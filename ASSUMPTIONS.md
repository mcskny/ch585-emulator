# CH585M Emulator — Hardware & Behavior Assumptions

Because no separate public CH585 Reference Manual is distributed alongside the datasheet, any behavior not explicitly spelled out in `CH585DS1_EN.PDF`, `CH585SFR.h`, `core_riscv.h`, and `sdk_exam/SRC/StdPeriphDriver/*.c` is documented here with its inference basis.

## Core & Memory
1. **ROM Config Area (`0x0007F000..0x0007F100`)**:
   - `ROM_CFG_CHIP_ID` (`0x0007F024` / `CH58x_sys.c`): initialized to `0x00000093` (matching `ID_CH585 = 0x93` in `CH585SFR.h`) unless overwritten by an ELF segment.
   - `ROM_CFG_MAC_ADDR` (`0x0007F018`): initialized to a deterministic non-all-FF 6-byte MAC address `[0x58, 0x50, 0x00, 0x12, 0x34, 0x56]` for `GET_UNIQUE_ID` / BLE.
   - `ROM_CFG_TMP_25C` (`0x0007F014`): initialized so `adc_to_temperature_celsius` yields ~25 °C at nominal temp ADC reading.
   - `ROM_CFG_ADR_HW` (`0x0007F00C`): bit 13 cleared so `PWR_DCDCCfg` does not bail out early.
2. **QingKe V3C Core (`crates/ch585-core/src/cpu/`)**:
   - `startup_CH585.S` executes in Machine mode from reset (`PC = 0x00000000`), configures `0xbc0`, `0x804` (`intsyscr`), `0xbc1`, `mstatus = 0x88`, `mtvec = _vector_base | 3`, `mepc = main`, then executes `mret` to enter User mode (`MPP=0`) with `MIE=1`.
   - `gintenr` (`0x800`) aliases `mstatus` bits 3 (`MIE`) and 7 (`MPIE`) and is permitted in User mode (as used by `CH58x_sys.c` / `core_riscv.h` via `csrrc`/`csrrs`).
   - `mtvec` mode 3 (low 2 bits == `0b11`): hardware reads the 32-bit absolute handler address from `(mtvec & !3) + 4 * cause`, and `mepc` points to the interrupted instruction. Exceptions and interrupts both index into `_vector_base` by cause/IRQn (`SysTick_IRQn = 12`, `SWI_IRQn = 14`, `TMR0 = 16`, ..., `LED = 39`).
   - HPE (`intsyscr` bit 0): hardware stacking saves `x1, x5..x7, x10..x17, x28..x31`, `mepc`, and `mstatus` internally up to 3 nesting levels (with overflow fallback), and restores them on `mret`.
   - `mcpy rd, rs1, rs2` (`opcode=0x0f, funct3=7, funct2=0`): copies bytes while `regs[rs1] < regs[rd]` from `regs[rs1]` to `regs[rs2]`, updating `regs[rs1]` and `regs[rs2]` in place per `__MCPY` in `core_riscv.h`.
   - `PFIC->SCTLR` bit 31 (`0x80000000`) triggers system reset (`PC = 0`, reset peripherals, `RST_FLAG_SW`).
3. **Privilege & `MachineMode_Call`**:
   - On real QingKe V3C, `main` runs in User mode while ISRs run in Machine mode. `MachineMode_Call` patches `_vector_base[SWI_IRQn]` and triggers `SWI_IRQn` (14) via `PFIC->IPSR` to execute privileged code in Machine mode. Emulating Machine/User privilege transitions accurately ensures `MachineMode_Call` and `mret` behave identically to silicon.

## Peripherals & Bridges
4. **PFIC Level-Driven Interrupts (`crates/ch585-core/src/pfic.rs`)**:
   - Peripheral hardware interrupt lines (`GPIO_A/B`, `TMR0..3`, `ADC`, `UART0..3`, `SPI0..1`, `PWMX`, `RTC`, `USBHS`) are modeled as level-driven sources synchronized via `Pfic::sync_level_irq`, rather than permanently latching into `IPSR`, so clearing a peripheral interrupt flag inside an ISR immediately deasserts its pending signal.
5. **System Control & Flash SPI (`crates/ch585-core/src/peripherals/sys.rs`)**:
   - `R8_GLOB_CFG_INFO` (`0x4000_1044`) defaults to `0x09` (`CFG_RESET_EN = 0`, matching `CH585DS1_EN.PDF` bit 2 `0` = reset disabled), while supporting Safe Access (`0x57` -> `0xA8`) unlock timing.
   - The internal Flash SPI controller (`0x4000_1800..0x4000_1807`) implements the JEDEC-style SPI flash command protocol (`0x9F`, `0x05`, `0x03`/`0x0B`, `0x06`/`0x02`/`0x20`/`0xD8`) backed by internal 512 KB flash + ROM config/calibration pages so `libISP585.a` (`FLASH_ROM_*` / `EEPROM_*`) operates directly.
6. **ADC Calibration & Scan (`crates/ch585-core/src/peripherals/adc.rs`)**:
   - `RB_ADC_IF_EOC` asserts `ADC_IRQn` whenever conversion completes (even if `RB_ADC_IE_EOC` in `R8_ADC_CTRL_DMA` is cleared, as used by polling/wait routines).
   - Writing `RB_ADC_START` (`R8_ADC_CONVERT`) clears `IF_EOC` and starts conversion if idle. Writing `R32_ADC_DMA_BEG` updates `R32_ADC_DMA_NOW`.
   - When `RB_ADC_OFS_TEST` is enabled, ADC conversion outputs `2047` mid-scale so `ADC_DataCalib_Rough()` computes `0` offset calibration.
7. **USB 2.0 HS Device Bridge (`crates/ch585-core/src/peripherals/usbhs.rs`)**:
   - `R8_USB2_INT_FG` bit 4 (`USBHS_UDIF_TRANSFER`) is read-only and dynamically derived from pending `DONE` (`0x80`) flags across endpoints.
   - Completed EP0 SETUP/OUT and EPx OUT transfers assert both `DONE` (`0x80`) and `USBHS_UEP_R_TOG_MATCH` (`0x10`) in `USBHS_UEPn_RX_CTRL`.
   - Instead of UTMI+ physical bit signaling, `UsbHs` embeds a virtual USB HS Host state machine that automatically executes Bus Reset, HS speed negotiation, standard control enumeration (reading Device, Config, Strings, and HID Report descriptors), and queues/captures EP1..EP7 IN/OUT DMA transfers.
8. **BLE / 2.4G / RF API Bridge (`crates/ch585-core/src/ble_stub.rs`)**:
   - `0x4000_C000..0x4000_DFFF` is routed to `BleBridge`, returning `0` on register reads (no baseband/RF register emulation; keeps `unknown_mmio` clean and avoids hardware-polling hangs).
   - ELF `.symtab` symbol hooks (`CH58x_BLEInit`, `GAPRole_SetParameter`, `HidDev_Report`, `GATT_Notification`, `RF_Tx`, `RF_Rx`) inspect/bridge high-level BLE/RF API activity (advertising status, adv/scan payload, HID reports, event log).
9. **USBHS Hot-Plug & Suspend/Remote Wakeup (`crates/ch585-core/src/peripherals/usbhs.rs`)**:
   - When firmware disables the device controller (`USBHS_UD_DEV_EN = 0`, link/SIE reset asserted, or `USBHS_PLL_EN = 0`) or host calls `detach()`, the virtual host resets its session (`enumerated = false`) and automatically initiates Bus Reset + full control enumeration once both `device_enabled()` and `host_attached` become true again.
   - `suspend()` asserts `USBHS_UDIF_SUSPEND` (`0x02`) and pauses SOF/EP polling; writing `USBHS_UD_UD_REMOTE_WKUP` (`0x01`) in `R8_USB2_WAKE_CTRL` clears suspend, increments `remote_wakeup_count`, asserts `USBHS_UDIF_LINK_RDY`, and auto-clears the control bit.
10. **Low-Power Modes, Current Estimates & LSE Failure (`crates/ch585-core/src/peripherals/sys.rs`, `soc.rs`)**:
   - MCU power state on `WFI` is classified from `PFIC->SCTLR` bit 2 (`SLEEPDEEP`), `R16_POWER_PLAN` bit 15 (`RB_PWR_PLAN_EN`), and `R16_POWER_PLAN` bit 2 (`RB_PWR_CORE`, per `CH58x_pwr.c`): `Idle`, `Halt`, `Sleep`, or `Shutdown`.
   - `Sleep` / `Shutdown` gate HF peripherals (`SysTick`, `TMR0..3`, `ADC`, `UART0..3`, `SPI0..1`, `PWMX`), while `RTC`, `GPIO`, and `USBHS` only wake the CPU when their `R8_SLP_WAKE_CTRL` bits (`0x08`, `0x10`, `0x02`) are enabled. `Shutdown` wakeup performs reset `0x05` (retaining SRAM when `RB_PWR_RAM32K` or `RB_PWR_RAM96K` is set).
   - `estimated_avg_current_ua()` uses nominal CH585 datasheet typical currents weighted by ns spent in each mode: Active `4000 uA` (DCDC on) / `6000 uA` (LDO), Idle `1800 uA`, Halt `300 uA`, Sleep `2.5 uA`, Shutdown `0.4 uA`.
   - When `lse_failed` is true and external 32 kHz XTAL (`RB_CLK_OSC32K_XT`) is selected, `RB_32K_CLK_PIN` stays `0` and `RTC` stops advancing.
11. **ADC Deterministic Noise & GPIO External Pulls (`adc.rs`, `gpio.rs`)**:
   - Per-channel `noise_mv[ch]` adds deterministic `xorshift64` jitter in `[-noise_mv, +noise_mv]` mV during hardware conversion steps (without modifying clean snapshot queries), clamped to `0..=3300 mV`.
   - `ExtPull::{PullUp, PullDown}` models weak PCB resistors (e.g. 100k pull-up/pull-down) effective when a pin is floating and internal MCU PU/PD are off; `check_contention()` logs strong opposing MCU output vs strong external digital drive.
12. **External Circuit API & Decoupled Board Plugins (`crates/ch585-core/src/ext.rs`, `crates/ch585-boards`)**:
   - `ch585-core` stays strictly chip-generic and exposes `ExternalDevice`, `on_pin_change`, `schedule_at_ns`/`schedule_after_us`, and `PinAnalogModel`.
   - `PinAnalogModel` computes node voltage (`compute_pin_voltage_mv`) via a resistive Millman network: MCU Push-Pull driver uses `~100 Ω` in 5 mA mode (`PD_DRV=0`) and `~25 Ω` in 20 mA mode (`PD_DRV=1`); MCU internal PU/PD uses `~40 kΩ`; external `ExtPull` uses `ext_pull_ohm` (default `100 kΩ`), combined with `source_ohm` and optional `load_ohm`.
   - All Macropad v2 hardware models (`RatiometricRail` gated by `PB16` with `VANA = rail/2`, `BatteryModel` `3700 mV` across `1M / 470k` -> `1183 mV` on `AIN13`/`PA9`, `74HC165`, `QuadEncoder`, `WS2812`, `BQ25300` active-LOW `PB7` EN) live outside `ch585-core` in `crates/ch585-boards` and attach solely through the chip's event/timer API.
13. **Power Domains, Reset Flags, VDD/BOR, Flash Timing/Corruption, Per-Peripheral Current & Sleep Time-Skipping (`sys.rs`, `rtc.rs`, `soc.rs`)**:
   - **Reset flags** (`R8_RESET_STATUS & 0x07` per `CH585SFR.h`): `0x00` = `RST_FLAG_SW`, `0x01` = `RST_FLAG_RPOR`, `0x02` = `RST_FLAG_WTR`, `0x03` = `RST_FLAG_MR` (`pin_reset`), `0x05` = `RST_FLAG_GPWSM` (`Shutdown` wakeup). Non-POR resets preserve `R8_GLOB_RESET_KEEP`; POR (`RST_FLAG_RPOR`) clears `R8_GLOB_RESET_KEEP` and SRAM.
   - **VDD / BOR & `BAT_DET` Monitor (`CH58x_pwr.h`)**: Default Brown-Out Reset (`bor_threshold_mv = 1750 mV`, `bor_hysteresis_mv = 50 mV`) powers off the MCU and clears SRAM when `vdd_mv < 1750 mV`, and releases into `RST_FLAG_RPOR` once `vdd_mv >= 1800 mV`. `PowerMonitor` implements LP thresholds `LPLevel_1V7..2V4` (`1700..2400 mV`, `1 uA`) and HA thresholds `HALevel_1V9..2V5` (`1950/2150/2350/2550 mV`, `210 uA`), asserting `WDOG_BAT` (or `NMI` when both `RB_BAT_LOW_IE` and `RB_BAT_LOWER_IE` are enabled).
   - **Flash SPI Timing & Power-Cut Corruption**: Page Program (`0x02`) defaults to `50 us` (`program_time_ns`) and Erase (`0x20`/`0x81`/`0x52`/`0xD8`) defaults to `200 us` (`erase_time_ns`), reporting `WIP=1` in RDSR (`0x05`) until committed on CS deassertion + elapsed duration. Power loss mid-operation (`power_off` / BOR / `--power-cut-flash <pct>`) increments `interrupted_ops` and leaves NOR-consistent partial corruption (`0 -> 1` partial byte at erase boundary, partial `1 -> 0` byte at program boundary, uncommitted suffix bytes unchanged).
   - **Per-Peripheral Current Breakdown (`CurrentTable` / `PowerReport`)**: Additive typical currents weighted by nanosecond active time (when clock-gated on and peripheral enabled): ADC `400 uA`, USBHS Active `12,000 uA` / Suspend `300 uA`, BLE RF `6,000 uA`, UART `100 uA/ch`, SPI `120 uA/ch`, TMR `80 uA/ch`, PWMX `80 uA`, HA `BAT_DET` `210 uA`, LP `BAT_DET` `1 uA`.
   - **Sleep / Idle O(1) Time-Skipping**: When unpowered or halted in `WFI` without pending wakeups or active byte-level transfers (`USBHS` unsuspended, active `ADC` conversion, non-empty `UART`/`SPI` FIFOs/DMA, active `PWMX`/Timer PWM), `run_us` fast-forwards in O(1) to the nearest `ExtHost` timer, Flash WIP completion, enabled `RTC` timer/trigger wakeup, `WDOG`/`IWDG` timeout, or (`Idle`/`Halt`) `SysTick`/`Timer` IRQ boundary.

14. **Performance & Fast-Path Architecture (`cpu/mod.rs`, `gpio.rs`, `ext.rs`, `soc.rs`)**:
   - **O(1) Bitwise GPIO (`gpio.rs`, `ext.rs`)**: `effective_pa_pin()`, `effective_pb_pin()`, `pin_level(port, idx)`, `check_contention()`, and `evaluate_interrupts()` operate purely with cached external drive/pull bitmasks (`ext_*`) and dirty tracking (`version`), with bitwise `GpioSnap` diffing in `ExtHost::poll` (zero per-cycle pin loops).
   - **Cached Basic-Block Execution (`cpu/mod.rs`, `soc.rs`)**: `run_fast_batch` executes up to `budget` cycles via a 4096-entry direct-mapped `CachedBlock` (`FastOp`, `MAX_BLOCK_OPS = 16`, XOR Flash/SRAM index mixing, `'self_loop` tight-loop fast path, and `len4_mask` O(1) mid-block PC recovery) with direct Flash/SRAM slices. Flash writes/erases (`FlashCtrl::write_epoch` -> `flash_version`), two-level SRAM SMC tracking (`sram_code_pages` 1 KB page bitmap + `sram_code_halfwords` exact 2-byte halfword bitmap), and block-entry 8-byte header (`raw_head`) preserve coherency without flushing on WCH `__ISB()` `FENCE.I` barriers (`Cpu::step` / `exec_insn` retains explicit `FenceI` invalidation).
   - **Batched Peripheral Stepping & `--exact` Mode (`soc.rs`, `tmr.rs`)**: By default (`exact_periph_step = false`, `periph_batch_cycles = 256`), CPU batches run up to 256 cycles and clamp `budget` to active peripheral edges (`ExtHost` timers, Flash WIP, `ADC` conversion end, `PWMX`, and `Timer` PWM/DMA edges including initial DMA FIFO prime), flushing accumulated peripheral cycles immediately on any MMIO, PFIC, or SysTick access or IRQ/sync event. Setting `--exact` (`exact_periph_step = true`) reverts to strict 1-cycle-per-instruction lockstep peripheral stepping.
15. **Tools & Hardware Calibration (`calibration.rs`, `vcd.rs`, `profiler.rs`, `report.rs`, `json.rs`)**:
   - **Zero-Dependency JSON & Combined Calibration (`calibration.rs`, `json.rs`)**: `TimingModel`, `AdcCalibrationModel`, and `CurrentTable` load cleanly from JSON without external crates (`serde` omitted to keep WASM size minimal). Default `TimingModel` fields are all zero (ideal 1 cycle/instruction). When any non-zero field is enabled, execution routes through `Cpu::step_sys` / `Cpu::run_timed_batch`, applying Flash (`flash_fetch_wait`) vs SRAM (`sram_fetch_wait`) fetch latency, taken branch, jump, load/store, MMIO access (`0x4000_xxxx` / `0xE000_Exxx..Fxxx`), interrupt entry/exit cycles, and active peripheral DMA bus-sharing stall penalties (`dma_bus_penalty_cycles` per active DMA source).
   - **ADC Linearity Curve & RC Settling (`calibration.rs`, `adc.rs`)**: Optional per-channel/per-gain calibration entries (`offset_mv`, `gain_scale`, `offset_counts`, piecewise-linear `curve_mv_to_counts`) plus hold-capacitor RC settling (`tau = (R_ext + R_int) * C_samp` scaled by `R8_ADC_CFG` clock divider `1.0x..2.25x`) apply in `Adc::step()` while keeping `sample_channel_mv()` and default behavior unchanged. External `PinAnalogModel::source_ohm` on `PA0..PA15` automatically populates `pin_source_ohm`.
   - **VCD Export (`vcd.rs`)**: `--vcd <path>` / `enable_vcd_trace()` captures change-compressed IEEE 1364 waveforms (`1ns` timescale) for selected or auto-discovered changing GPIO pins (`gpio`) together with internal `irq_active`, `irq_depth`, `dma_mask` + individual DMA channel bits (`tmr0..3`, `adc`, `spi0..1`, `usb`), `usb_attached`/`usb_enumerated`/`usb_suspended`/`usb_in_tog`/`usb_out_tog`/`usb_ep`, and `power_mode`.
   - **ELF Symbol, ISR & Stack Profiler (`profiler.rs`, `elf.rs`)**: Tracks function `calls` (`JAL`/`JALR` with link register `x1`/`x5`), self cycles/ns resolved against ELF `.symtab` function ranges, nested/longest ISR latency between PFIC entry and `Mret`, and `sp` low-water mark + overflow events restricted to valid SRAM addresses (`0x2000_0000..=0x2002_0000`) against `_eusrstack`..`_ebss` (or `--stack-limit`).
   - **Machine-Readable Diff JSON (`report.rs`, `--json`)**: Emits `schema_version = 1` structured JSON (CPU, clock, time, power breakdown, GPIO, UART text/hex, decoded USB HID NKRO/EP4 vendor telemetry, BLE bridge state, `unknown_mmio`, optional `profile`, `perf`, and `board`). `MachineReport::to_diff_json_string()` omits wall-clock `perf` so differential runs across simulator versions or hardware logs are byte-deterministic.
16. **Multi-Chip Simulation, 2.4 GHz RF (`wchrf.h`) Bridge & Virtual BLE Central (`cluster.rs`, `rf.rs`, `ble_stub.rs`, `cpu/mod.rs`)**:
   - **Closed-Source Radio/BLE API Bridging Rationale (`ble_stub.rs`, `rf.rs`)**: `libCH58xBLE.a` / `wchrf` baseband hardware registers (`0x4000_C000..0x4000_DFFF`) are undocumented and proprietary; rather than gate-level RF hardware registers, the emulator bridges `wchrf.h` and BLE GAP/GATT/Bond/TMOS/LowPower at ELF `.symtab` symbol + callback ABI boundaries.
   - **Guest RV32 Callback Trampoline (`cpu/mod.rs`)**: Host-dispatched guest callbacks (`rfProcessCB`, `rfBoundCB`, `pfnStateChange`, `pfnParamUpdate`, `pairStateCB`, `pfnReadAttrCB`, `pfnWriteAttrCB`, `GATT_bm_free`) run natively on the RV32 CPU with `ra = CALLBACK_RET_SENTINEL (0xFFFF_FFE0)`, 16-byte-aligned caller-frame argument blobs above callee `sp`, non-reentrant FIFO dispatch outside active ISRs, and zero hot-path overhead on `run_fast_batch` block cache hits.
   - **2.4 GHz RF Fast/Bound & Basic Medium (`rf.rs`)**: Supports `RF_DMADESCTypeDef` TX/RX descriptor rings (`STA_DMA_ENABLE`), `rfBoundHost_t`/`rfBoundDevice_t` pairing (`RF_BOUND_ID = 7`) and bonded reconnect, `RFIP_SetTxParm`/`RFIP_SetRx` Basic frames, and shared `RfMedium` modeling deterministic `xorshift64*` packet loss, propagation latency + jitter, per-channel interference (`channel_interference_dbm[40]` degrading RSSI and injecting `RF_STATE_RX_CRCERR`), and link-drop/timeout (`BOUND_STA_TIMEOUT`, `RF_STATE_TIMEOUT`, `RF_STATE_RBU`).
   - **Virtual BLE Central & DataFlash SNV Bonding (`ble_stub.rs`, `soc.rs`)**: Drives full scan -> connect -> pair/bond -> GATT attribute read/write/CCCD -> HID/GATT notification capture (with `GATT_bm_free` cleanup to prevent `MEM_BUF` heap exhaustion) -> connection parameter update -> disconnect -> reconnect lifecycle. Bond records persist in a CRC32-protected `CH58BOND` 256-byte DataFlash SNV block (`SNVAddr` resolved from `BLE_LibInit` or default `0x77E00`) surviving soft resets, power cycles, and `--flash-out`/`--flash-in`. Tracks `tmos_start_task`/`tmos_start_reload_task`/`tmos_stop_task` and `CH58x_LowPower`/`LowPower_*` hooks compatibly with CH585 `Sleep` O(1) time-skipping and radio power accounting (`radio_active()`).
   - **Multi-Chip Synchronous Cluster (`cluster.rs`)**: Advances multiple `Ch585Machine` instances synchronously in configurable quanta (`quantum_us = 50` µs default), auto-assigning distinct factory MAC suffixes if still default, propagating inter-chip `GpioWire` drive/pull/contention without feedback latches, and streaming `UartWire` TX logs into peer RX FIFOs with 8-byte hardware FIFO backpressure.
17. **Real-Time Block Execution with Live External Board Models (`ext.rs`, `soc.rs`, `cpu/mod.rs`, `tmr.rs`, `pwm.rs`, `adc.rs`)**:
   - **Zero-Allocation Scoped Device API (`Ch585Machine::run_us_with`, `run_cycles_with`, `step_with`)**: External board structs owning `Ch585Machine` alongside board state can borrow `&mut board` directly onto the fast block path (`run_fast_batch` + O(1) Sleep fast-forward) without `Rc<RefCell>` wrappers or per-event heap allocations, alongside existing persistent `attach_device(Box<dyn ExternalDevice>)`.
   - **Pin Watch Filtering (`PinWatchMask`) & Clean Driver Fast Path**: External devices declare relevant pins via `watched_pins()` (`ALL` by default for backwards compatibility). Unwatched pins are masked out in `ExtHost::poll_with` before allocating/computing `PinChangeEvent` and resistive Millman voltages (`compute_pin_voltage_mv` also shortcuts push-pull outputs with no external pull, drive, or load). `PinContext` exposes `gpio()`, `adc()`, `pin_is_output()`, `mcu_output_level()`, `cancel_timer()`, and `reschedule_at_ns`/`reschedule_after_ns`/`reschedule_after_us` (used by `MacropadV2Board` to avoid stale WS2812 latch timers).
   - **Pre-Read Input Synchronization (`InputReadMask` / `on_before_input_read`)**: When any active external device declares `InputReadMask` bits (`GPIO_A`, `GPIO_B`, `ADC`), CPU reads of `PA_PIN` (`0x4000_10A4..=0x4000_10A7`) or `PB_PIN` (`0x4000_10C4..=0x4000_10C7`) — checked strictly inside the MMIO branch of `fast_load!` with zero SRAM/Flash overhead — flush preceding peripheral cycles, deliver `on_before_input_read` at the exact cycle/nanosecond timestamp before the load executes, and retry the load cleanly. `InputReadKind::Adc` fires at exact conversion completion (`Adc::step` pre-sample check across single-shot, continuous, and DMA scan modes) after splitting preceding cycles so sample voltages match `step()` to the cycle.
   - **Device-Pulled Deadlines (`next_event_ns` / `on_time_reached`) & Exact Short-Pulse Edge Parity**: Devices can supply dynamic next-event deadlines (`next_event_ns()`) without heap timer pushes; both `run_batch` cycle budgets and `try_fast_forward` (unpowered / Idle / Sleep) clamp to the minimum of internal timers and `next_event_ns()`, firing `on_time_reached` when reached. MMIO writes to `TMR0..3`, `PWMX`, `ADC`, and `RTC` trigger `mmio_sync_requested` mid-batch, `flush_pending_peripherals()` flags mid-batch `gpio.version` transitions, `Timer::next_edge_cycles()` checks `pwm_out != ((count < duty) ^ polar)` so narrow initial pulses at `count == 0` are never skipped, and `PwmX::next_edge_cycles()` computes exact ticks to the earliest active channel/period transition. Back-to-back GPIO toggles and narrow peripheral PWM pulses preserve both rising and falling edges in chronological order with exact timestamps.

18. **Cycle-Exact Batch Clamping & USB-Active Idle Fast-Forward (`phase6_timing_and_idle_fastpath_tests.rs`)**:
   - **Batch Budget Clamping & MMIO Sync**: `Ch585Machine::run_batch_inner` also clamps its cycle budget to deliverable `SysTick::next_irq_cycles()`, `Timer::next_irq_cycles()`, `UsbHs::next_event_cycles()`, `Rtc::next_wakeup_sys_cycles()`, `Uart::next_event_cycles()`, `Spi::next_event_cycles()`, and `SysCtrl::next_wdog_cycles()`, and `SysBus::mmio_write_{u8,u32}` sets `mmio_sync_requested = true` on `UART0..3`, `SPI0..1`, and `USBHS` writes. This eliminates up to-255-cycle interrupt/transfer deferral drift between `periph_batch_cycles = 256` and single-step (`periph_batch_cycles = 1`).
   - **Idle/WFI Fast-Forward with Active USB HS**: `Ch585Machine::try_fast_forward_inner` advances `!deep` (`Idle` / `Halt`) `WFI` windows in O(1) even while USB HS is enabled, attached, and unsuspended, using exact `time_ns_rem`, `Rtc::step_u64`, `SysCtrl::step_u64`, `SysTick::advance_cycles`, `Timer::advance_cycles`, `Adc::advance_idle_cycles`, and `UsbHs::advance_idle_cycles`, stopping 1 cycle prior to observable USB/ADC events so `UsbHs::step` / `Adc::step` and pre-sample device hooks run cycle-accurately. Simultaneous Idle fast-forward blockers (USB, ADC, PWM/DMA timers, PWMX, UART, SPI, OSC calibration, short device/timer windows) are counted independently in `SysBus::idle_skip_stats` (`IdleSkipStats`).

19. **QingKe V3C HPE Unstack Bypass (`INTSYSCR` Bit 5) & Nested Trap CSR Stacking (`cpu/mod.rs`, `pfic.rs`)**:
   - **Single-Exit HPE Unstack Suppression (`0x804` bit 5 = `0x20`)**: When an RTOS context-switch handler (`SW_Handler` in WCH FreeRTOS, RT-Thread, or HarmonyOS ports) runs with `HWSTKEN=1` (`intsyscr & 1 != 0`), manually restores all GPRs and writes the incoming task's PC to `mepc`, and executes `csrs 0x804, 0x20`, the next `Mret` pops and releases the active `HpeFrame`/PFIC active state without restoring the 16 HPE GPRs or overwriting `mepc`/`mstatus`, and automatically clears bit 5 (`0x20`) of `intsyscr`.
   - **Non-Nested `Mret` Privilege/CSR Preservation & Nested CSR Stacking**: `HpeFrame` stores outer `(mepc, mstatus, mcause)` (`nested_trap_ctx`) only when `enter_interrupt` nests inside an already-active IRQ (`!active_irqs.is_empty()`). On depth-1 `Mret`, privilege and return address decode directly from current `mstatus` (`MPP`/`MPIE`) and `mepc` (preserving `Privilege::Machine` across normal `Mret`s even when an earlier `Mret` reset `MPP=0`). On nested `Mret` (without bit 5 suppression), `outer_mepc`, `outer_mcause`, and `outer_mstatus` (with `MIE` updated from inner `MPIE`) are restored for the resumed outer handler.
   - **`SysTick->CTLR` Bit 31 (`pfic.rs`)**: While CH585 SDK code triggers `SWI_IRQn` (14) via `SysTick_SR_SWIE` (`0xE000_F004` bit 31) or `PFIC->IPSR`, writing bit 31 of `SysTick->CTLR` (`0xE000_F000`) also pends `SWI_IRQn` (14) rather than `SysTick_IRQn` (12).
